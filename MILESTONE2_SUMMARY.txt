QUICK START COMMANDS
====================

1. Ensure database is running:
   docker compose up -d postgres redis

2. Install dependencies:
   cd backend
   pip install -r requirements.txt

3. Run migrations:
   cd backend
   alembic upgrade head

4. Verify schema:
   docker compose exec postgres psql -U lecturesync -d lecturesync -c "\dt"

5. Run tests:
   cd backend
   pytest tests/test_models.py -v

6. Rollback migration (if needed):
   cd backend
   alembic downgrade -1

7. Create new migration for schema changes:
   cd backend
   alembic revision --autogenerate -m "Describe your change"

ARCHITECTURE DECISIONS
======================

UUID Primary Keys
- All tables use UUID (RFC 4122) as primary key
- Generated via Python uuid.uuid4()
- Advantages: globally unique, partition-friendly, can be generated client-side
- Disadvantage: larger than integers (but negligible for modern databases)

Async SQLAlchemy
- Uses sqlalchemy==2.0.43 with async support
- Driver: psycopg[binary]==3.2.9 (async PostgreSQL driver)
- All database operations are async/await compatible
- Enables non-blocking I/O in FastAPI handlers

Enums
- PostgreSQL native ENUM types for data integrity
- LectureStatus, JobStatus, JobType defined in models
- Created automatically by migrations

Timestamps
- created_at: Set once at creation, never updated
- updated_at: Updated on every row modification
- Stored as DateTime in UTC
- Useful for audit trails and data reconciliation

Soft Deletes
- NOT implemented (out of scope for Milestone 2)
- Records are permanently deleted
- If soft deletes needed later, add is_deleted boolean and update queries

DATABASE INTEGRATION NOTES
==========================

For Local Development (host):
- DATABASE_URL uses localhost: postgresql+psycopg://lecturesync:password@localhost:5432/lecturesync
- REDIS_URL uses localhost: redis://localhost:6379/0

For Docker Containers:
- DATABASE_URL uses service name: postgresql+psycopg://lecturesync:password@postgres:5432/lecturesync
- REDIS_URL uses service name: redis://redis:6379/0

The .env file stores the correct values. When running migrations or tests locally,
ensure you're using the localhost version. When running inside Docker, environment
variables should override to use service names.
